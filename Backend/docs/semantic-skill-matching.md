# Semantic skill matching

The interview report generator adds an explainable `skillMatches` result for
each job-description skill. Exact and catalogued alias matching is checked
before embedding inference. Remaining requirements are compared with the local
`onnx-community/all-MiniLM-L6-v2-ONNX` model using 384-dimensional normalized
embeddings. Results are classified as `Exact Match`, `Alias Match`,
`Semantically Related`, `Needs Review`, or `Missing Skill` using the thresholds
in `src/config/semanticSkillMatching.json`.

`Semantically Related` means that terms are close in embedding space. It does
not establish equivalent proficiency or experience. Each result carries the
candidate evidence source, section, excerpt, polarity classification and
similarity so a reviewer can inspect the result. If local embedding inference
is unavailable, exact and alias results remain available and other
requirements are marked `Needs Review`.

The model is loaded lazily on CPU and cached for the process. The first use may
download model assets and needs network access unless the model is already
cached. `@huggingface/transformers` is a runtime dependency because report
generation uses it in production.

## Evidence polarity and score boundaries

Before exact or semantic matching, candidate excerpts are assigned one of five
evidence states: Positive Assertion, Negative Assertion,
Uncertain/Familiarity-only, Learning/In-progress, or No Evidence. Exact and
alias matches require positive evidence. A negative exact mention is classified
as Missing Skill; an uncertain, learning, or unverified mention is Needs Review.
Negative mentions are excluded from semantic candidate selection. A skill
listed under a recognized skills section is treated as uncertain because a
keyword list does not establish practical experience. The classifier preserves
the source excerpt and section for review.

Evidence polarity uses contextual language rules around the extracted skill
mention. It is a conservative heuristic, not a language-entailment model; mixed,
ambiguous, or unusual phrasing can still require human review. Job requirements
that canonicalize to the same catalog skill are grouped before matching. Their
original matched wording, source, section, and excerpt are retained as
`requiredEvidence` on the result.

The report's `matchScore` remains the separate score generated by Gemini in the
existing report workflow. Phase 4.1 does not change its formula, weights, or
penalties, and does not combine cosine similarity with that percentage. No
deterministic resume-JD scoring formula is introduced here. Cosine similarity
is a pairwise embedding measure; it is not the final report percentage.

## Synthetic benchmark

Run `npm run benchmark:skills` from `Backend/`. The script embeds the labeled
synthetic examples in `benchmarks/skills/dataset.json`, calibrates the review
and semantic thresholds, compares with exact/alias-only matching, and writes
results to `benchmarks/skills/results.json`.

The expanded benchmark has 37 labeled term pairs across exact, alias, true
semantic, related-but-non-equivalent, unrelated, and ambiguous relationships,
plus six evidence-polarity fixtures. Direct pairs include REST APIs/API
Development, Frontend Development/React.js, Node.js/Express.js,
Docker/Kubernetes, TensorFlow/PyTorch, Docker/Python, AWS/MongoDB,
Java/JavaScript, React.js/HTML, TensorFlow/SQL, C++/CPP, and Machine
Learning/ML. Expected labels are specified in the dataset independently of
embedding output. The set is small and does not represent naturally occurring
resume evidence.

Measured exact/alias-only baseline accuracy is 0.514 (macro-F1 0.505). Hybrid
accuracy/macro-F1 on the threshold calibration set is 0.811/0.847. Leave-one-out
evaluation, where thresholds are recalibrated without each held-out pair, is
accuracy 0.676 and macro-F1 0.745. In leave-one-out evaluation,
Semantically Related precision/recall/F1 is 0.500/0.571/0.533; Needs Review is
0.455/0.455/0.455; Missing Skill is 0.778/0.700/0.737. Exact and alias
precision/recall/F1 are each 1.0 on supports of four and five examples. These
are synthetic-set measurements, not production accuracy estimates. The six
evidence fixtures classified into their expected polarity categories, but that
small result does not validate the rules on real-world phrasing.

Current thresholds (`reviewThreshold` 0.23849, `semanticThreshold` 0.49629)
were recalibrated from the full expanded synthetic set. Leave-one-out results
are more informative but still small-sample estimates. The benchmark currently
predicts Semantically Related for REST APIs/API Development and
Node.js/Express.js, although their independent expected labels are Needs
Review. Human review remains necessary. Expand and independently label a
representative dataset before treating classifications as validated for hiring
decisions.
